# Blushing snow — сайт клана

Отдельный проект на Django 5.2 LTS. Доска почёта ЛВК, рейтинг обычных КВ, состав с поиском, страницы текущих и бывших участников, явка, атаки и история развития. Адаптирован для телефона.

GitHub Pages публикует **статический экспорт** Django. Сам Django работает локально при разработке и в GitHub Actions при сборке. Сервер Django, SQLite и токен CoC на GitHub Pages не нужны. Официальная документация: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## Локальный запуск

Команды из этой папки:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Открыть http://127.0.0.1:8000/. Миграции не нужны: сайт читает подготовленный публичный снимок `data/clan.json`.

## Обновление данных из существующего проекта

После очередного сбора CoC, из папки сайта:

```sh
.venv/bin/python import_snapshot.py --source ..
.venv/bin/python manage.py export_site
```

`--source` — каталог действующего сборщика, `--db` позволяет указать другую БД. Чтение SQLite идёт только в read-only режиме. В публичный JSON попадают только явно перечисленные поля. Внутренние отметки ЛВК, кандидаты на исключение, raw JSON, пути файлов и API-токен не экспортируются. Стабильные URL игроков используют хеши вместо тегов.

Собранный сайт лежит в `_site/`. Он работает без Django:

```sh
.venv/bin/python -m http.server 8001 --directory _site --bind 127.0.0.1
```

Сайт — опубликованный снимок. Чтобы новые результаты увидели соклановцы, нужно обновить `data/clan.json`, закоммитить и отправить его в GitHub. Текущий ETL этим проектом не изменён; автоматическую публикацию можно подключить отдельно.

## Публикация на GitHub Pages

1. Создать новый репозиторий и загрузить **содержимое этой папки** в его корень, а не весь проект сборщика. Не добавлять `.venv` и `_site`: они исключены через `.gitignore`.
2. Основная ветка — `main`.
3. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
4. После push workflow `.github/workflows/pages.yml` проверит проект, соберёт HTML и опубликует Pages.
5. Адрес сайта будет в GitHub Actions и Settings → Pages. Относительные ссылки работают и на `username.github.io`, и на `username.github.io/repository/`.

Сайт, вариант 1: https://rememberedgirl.github.io/

Вариант 2, сохранённый дизайн «Берсерк»: https://rememberedgirl.github.io/berserk/

Репозиторий: https://github.com/RememberedGirl/rememberedgirl.github.io

Публикация включена через GitHub Actions. Push в `main` автоматически запускает проверки, сборку и обновление Pages.

## Как считаем

- ЛВК и обычные КВ разделены; рейтинг — по звёздам, добавленным клану, затем по доле явок и средним звёздам.
- В рейтинг попадают только текущие участники, имеющие известный состав в завершённых войнах.
- 1+ сохранённая атака — явка; 0 — пропуск. Подготовка и текущая война не начисляют пропуск.
- Успешная атака — 2+ звезды. Звёзды клану — улучшение предыдущего лучшего результата на цели.
- Незафиксированная атака считается отсутствующей, включая неполные снимки завершённых войн.
- «Дни с нами» — дни с первого наблюдения, а не подтверждённая дата вступления.
- В профиле — вся сохранённая история, в том числе после ухода из клана. Подробности атаки доступны раскрытием войны.

## Отдельная страница Masters of War

https://rememberedgirl.github.io/2PQQ2RJ0R/ — клан `#2PQQ2RJ0R`, собственный баннер и оформление, актуальный состав с поиском и сортировкой по ТХ и рейтинговой лиге. Снимок хранится отдельно: `data/clans/2PQQ2RJ0R.json`. Главная SQLite не изменяется.

Обновить снимок из каталога сайта с использованием окружения существующего сборщика:

```sh
../.venv/bin/python import_clan.py --source .. --tag '#2PQQ2RJ0R'
.venv/bin/python import_snapshot.py --source .. --db ../clans/2PQQ2RJ0R/clan_analytics.db --clan-name 'Masters of War' --output data/clans/2PQQ2RJ0R-history.json
git add data/clans/2PQQ2RJ0R.json data/clans/2PQQ2RJ0R-history.json
git commit -m "Refresh Masters of War roster"
git push
```

Для самостоятельного запуска импортёра нужны `requests` и `python-dotenv`; они уже есть в окружении сборщика. GitHub Actions не обращается к CoC API и не требует API-токен.


## Профили: клановые игры, рейды и армия

Во всех вариантах сайта и в обоих кланах профиль содержит:

- очки текущих клановых игр, накопленный вклад и историю по месяцам;
- последний сохранённый рейд, суммарное золото и атаки, историю рейдов;
- текущий вес армии и вес с обоими зельями, дату обновления профиля.

Клановые игры считаются по сохранённому приросту и ручным результатам, не по общему достижению аккаунта. Если есть лишь начальная точка, показывается «—». Рейды до первого наблюдения игрока в этом клане не включаются. Армии ушедших игроков не восстанавливаются: по принятому правилу хранятся только текущие армии.

Профили Masters of War используют `data/clans/2PQQ2RJ0R-history.json`, сформированный из отдельной исторической базы. Если этот снимок существует, состав страницы берётся из него; импорт API обновляет описание и свойства самого клана. Для полного обновления страницы нужно пересоздать и исторический снимок командой выше.

В профилях обоих кланов также есть графики уровня ратуши и отданных/полученных войск. Используются дневные строки `snapshots`, дни без снимков не восстанавливаются. Ратуша рисуется ступенчатой линией. Падение сезонного счётчика разрывает линию подкреплений и отмечается пунктиром; неизвестные значения не заменяются нулём. При одном дне наблюдения показывается точка.

## Матрица атак

На страницах обоих кланов есть матрица: текущие игроки по строкам, фактическая ТХ цели по столбцам. Крупное число — средние звёзды по сохранённым атакам, мелкое — число атак. Нулевые результаты включены; пустая ячейка не считается нулевой атакой, поскольку неизвестна цель. В матрицу включены сохранённые атаки КВ и ЛВК, включая текущий бой. Сортировка игроков — по текущей ТХ; ТХ цели — на момент атаки. Есть отдельный поиск и ссылка на профиль по нику.

Матрица ограничена компактной шириной. В каждой строке светлая рамка отмечает текущую ТХ игрока; соответствующий столбец присутствует, даже если атак по этому уровню ещё нет.
